# tools/ — 管理者手動工具（不隨 clasp 部署）

這裡的檔案**不屬於**表單 web app 本體（clasp 只推送 `appscript/`），是管理者視需要手動貼進
Apps Script 編輯器執行的輔助腳本。

| 檔案 | 用途 | 注意事項 |
|------|------|----------|
| `export.js` | 「問卷列表」試算表 container-bound GAS 的原始碼（手動貼上該試算表的 Apps Script 專案）。onOpen 建「問卷管理」選單九項：**新增問卷**（貼對照表單 ID → 格式檢查 → 建填入表＋列表新列）、**建立新問卷骨架**（從零建結構表示範欄＋填入表＋列表列）、**欄位輔助精靈**（勾選題型生成 8 格欄位設定「EXIF」，過檢查器驗證後複製直貼或直接寫入）、**修改問卷設定**（點選列開對話框：截止時間 datetime-local 日曆選、布林下拉、四個說明欄有輕量 markdown 編輯器＋預覽；B/C/N 唯讀）、**修改問卷內容**（開結構表連結＋有紀錄警語＋改完跑檢查）、**輸出問卷**（匯出點選列，取代舊「輸出主控台」分頁）、**檢查問卷格式**（完整檢查，規則見 `plan/2026-summer.md`）、**定時匯出排程**（對話框：問卷下拉選、時間日曆選、新增／修改／停用）、**立即試跑定時匯出**。定時匯出＝管理者自行掛時間觸發器（建議凌晨）跑 `scheduledExport()`，逐列判斷「頻率到了」且「上次匯出後有新填答」才真的匯出，匯完回寫該列並寄通知信；細節見下方「定時匯出」段 | ScriptProperties：`exportStorage`（匯出資料夾，必要）＋選填 `referStorage`（結構表資料夾）、`recordStorage`（寫入表資料夾）、`webAppAccount`（web app 執行帳號，供填入表保護編輯者）。**兩個資料夾各共享一次給執行帳號（結構表夾檢視權、寫入表夾編輯權），之後建的表自動繼承，免逐卷共享**。填入表建立時自動 protect（僅擁有者＋webAppAccount 可編輯）。「輸出主控台」分頁可刪、「執行紀錄」分頁必須保留。⚠️ 對話框按鈕（google.script.run）以瀏覽器**預設帳號**執行——多帳號登入時若預設非管理員帳號會 PERMISSION_DENIED，請用只登管理員帳號的視窗（無痕/獨立 profile）操作；onOpen 有 alert 提醒 |
| `fileOutput.js` | 更名機器人：讀取試算表中的 Drive 檔案連結清單，複製檔案到指定資料夾並依 C 欄字串重新命名 | 與表單系統無關的獨立工具 |

## 定時匯出（`export.js`，2026-07-28）

「問卷列表」試算表裡的 **「定時匯出」分頁**是設定表，一列一條排程。管理者到 Apps Script
編輯器 →「觸發條件」→ 新增時間驅動觸發器指向 **`scheduledExport()`**（建議每天凌晨；
比照 `Code.js` 的 `rebuildDraftSpreadsheet`／`scanLoginLog`，**程式不自建 trigger**）。

**設定一律走選單「定時匯出排程（新增／修改）」的對話框**，不必自己開分頁編欄位：問卷用**可搜尋的
下拉組合框**（輸入名稱或列號即時篩選，↑↓ 選擇、Enter 確定；選項顯示「［已排程］第 N 列・名稱」，
列號自動帶入不會打錯，問卷多也不必捲）、截止時間用 datetime-local 日曆選
（存回毫秒 timestamp）、其餘欄位有預設值——新排程的截止時間帶問卷的檢視截止、通知信箱帶列上的
管理員Email。選到已排程的問卷會載入現有設定並顯示上次匯出時間與結果，改完按儲存即覆蓋同一列。
分頁不存在時由 `ensureScheduleSheet_` 自動建好表頭。「立即試跑定時匯出」可在掛觸發器前驗證設定。

**停用**：對話框下方的「停用這條排程」把狀態欄寫成「已停用」，排程即跳過該列；**資料列保留不刪**
（禁刪列規範），之後在對話框按儲存就會恢復。

| 欄 | 內容 | 說明 |
|----|------|------|
| A | 問卷列號 | 「問卷列表」分頁上的列號，由對話框的下拉選單自動帶入 |
| B | 問卷名稱 | 對話框存檔時自動寫入當下名稱。之後**每次執行都會比對**列上名稱，對不上就停手不匯出（列表被排序或插刪列時，列號會指到別份問卷）；手動改名後回對話框重存一次即可 |
| C | 匯出頻率 | 每幾天匯一次，`1`＝每天 |
| D | 匯出截止 | 可直接填日期（Sheets 日期選擇器）或毫秒 timestamp。**到期後補做最後一次匯出**（不看頻率、不看有無新填答），寄信說明排程結束，K 欄寫「已結束」不再執行；把截止時間往後改會自動復活 |
| E | 通知Email | 多筆用分號分隔，留空＝不寄信 |
| F | 標題列數 | 留空＝2（欄位ID＋欄位名稱兩列），對應手動匯出的第一個問答 |
| G | 只留最新一筆 | 留空或「是」＝同一人只輸出最新一次，「否」＝每筆都輸出 |
| H~K | 上次匯出時間（ms）／上次輸出行數／上次結果／排程狀態 | **程式回寫，請勿手動改**；狀態為空＝進行中、`已結束`＝過了截止並做完最後一次、`已停用`＝人為喊停 |

行為要點：

- **有新填答才匯**：比對紀錄表的資料行數與最新送出時間 vs H/I 欄登記值，兩者都沒動就安靜略過
  （只讀送出時間那一欄判斷，不整張撈）。
- **新輸出的分頁固定插在最前面**（`insertSheet(name, 0)`），手動輸出同步改成這樣。
- **單次執行守門**：跑滿 4.5 分鐘就收工，沒輪到的排程留到下次觸發（GAS 單次上限 6 分鐘）；
  `ScriptLock` 防重疊；單列出錯只記在該列的「上次結果」欄，不拖垮整輪。
- **自動開檢視權**：寄信前先確認每個通知對象對匯出檔有權限，沒有的就 `addViewer` 補上檢視權
  （信到的時候連結就點得開，不會是「你需要存取權」）。已是擁有者／編輯者／檢視者的人跳過，
  **只加不降權**；授權失敗（例如網域政策擋外部帳號）會把名單寫進該列的「上次結果」欄要人工處理。
- 通知信只給統計與檔案連結，**不放任何填答內容**。
- 一併修掉的舊行為：輸出檔改用**檔名精確比對**搜尋（原本 `title contains` 會誤中前綴相同的問卷，
  自動排程匯錯檔沒人會當場發現）；新建的輸出檔**建完就搬進 `exportStorage`**（原本只在有資料時才搬，
  空跑會在雲端硬碟根目錄留孤兒檔）；`SpreadsheetApp.getUi()` 改成 lazy（觸發器沒有 UI，
  原本的全域求值會讓定時執行連函式都進不去）。

## 匯出表頭對齊（`export.js`，2026-07-31）

輸出的資料列跟紀錄表**不是同一種排法**：`injectRefer` 會把固定欄的「簽名檔ID」一格拆成
n 格簽名連結（放在分組後面），並丟掉對照表單沒設定（type 不在 `G|O|C|A|P|F`）的欄。
但表頭原本是從紀錄表**原樣抄過來**的，所以：

- **簽名格 1 格時剛好對上**（拆成 1 格＝原本 1 格），2 格以上整排答案往右錯一格、
  0 格則往左錯一格——錯得很整齊，欄位名跟答案都在、只是全部對錯人。
- 少簽一格的列會比別人短，舊碼是**往右補空字串**，等於把錯位固定下來，只在 log 留一句
  「可能是簽名檔遺失」。
- 主鍵不在名冊的列（名冊事後被改過／刪過人）舊碼直接吐紀錄表的原始排法，混在輸出裡自成一格。

現在改成表頭與資料共用同一套排法：先掃全表取**最大簽名格數**，每列一律補滿（沒簽的補
`無簽名`），表頭用 `remapHeaderRow_` 按同一組欄索引（`exportDataCols_`）重組——固定欄變成
`送出時間／有效／主鍵／分組`，接著 `簽名檔連結1…n`，再接題目欄。**新輸出的表頭與舊輸出檔不同**
（多了簽名欄、固定欄少一格），舊分頁留在原檔案不會被動到。「長度對不起來」的檢查留著當
最後一道防線，正常情況恆為 0。
